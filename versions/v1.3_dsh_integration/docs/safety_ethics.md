# BTCU Harness 安全与伦理规范

> **文档定位**：定义 BTCU 认知架构的安全模型、威胁防御与伦理准则。
> **适用版本**：BTCU Harness v1.x
> **核心原则**：安全不是附加层，而是认知架构的骨架。

---

## 1. 概述

传统软件安全关注数据完整性和访问控制。认知架构面临更深层问题：**系统不仅处理信息，还会改变自身**。

BTCU 的三态认知模型（Bind/Challenge/Unbind）允许 Agent 切换状态、学习模式、调整维度评估、修改价值观权重。这种自适应性是能力来源，也是风险来源。

| 风险类型 | 传统系统类比 | BTCU 中的后果 |
|---------|-----------|-------------|
| 输入操纵 | SQL 注入 | Agent 被强制进入特定认知状态 |
| 自层篡改 | 权限提升 | 任务/价值观/身份层被修改 |
| 记忆投毒 | 数据库篡改 | 虚假经验被当作真实历史 |
| 模式注入 | 代码注入 | 恶意行为模式被学习并固化 |

BTCU 采用**纵深防御**策略，在认知架构每一层嵌入安全机制：输入验证 → 状态锁定 → 模式校验 → 记忆衰减 → 自层对齐 → 行动抑制。核心信条：**认知可以演化，但不能被劫持。**

## 2. 威胁模型

### 2.1 三态操纵（Three-State Manipulation）

攻击者构造输入序列，迫使 Agent 按 Bind→Challenge→Unbind 预设路径切换，最终引导至对攻击者有利的认知状态。

```
攻击序列示例：
  输入1（高确定性信号）→ 强制 Bind
  输入2（弱矛盾信号）  → 触发 Challenge
  输入3（模糊信号）    → 推向 Unbind（void 态）
  结果：Agent 进入高不确定性状态，决策能力下降
```

**防御要点**：状态转移由维度评估驱动，非由单一输入决定；void 态保留多可能性而非丧失判断力。

### 2.2 自层篡改（Self-Layer Tampering）

攻击者尝试修改自层结构——任务层（Mission）、价值观层（Values）、身份层（Identity）——以改变核心行为准则。

| 自层组件 | 默认稳定性 | 篡改后果 |
|---------|-----------|---------|
| Mission | 0.95（近不可变） | Agent 目标偏移 |
| Values | 可调但有约束 | 决策过滤标准改变 |
| Identity | 维度锁定保护 | 自我认知错乱 |

### 2.3 记忆投毒（Memory Poisoning）

向状态记忆注入虚假经验：注入虚假成功记录使 Agent 重复有害行为；注入虚假失败记录使 Agent 回避有效策略；篡改 `suppressed_decisions` 解除对恶意行为的抑制。

### 2.4 模式注入（Pattern Injection）

攻击者构造输入序列，使 `PatternLearner` 将恶意行为模式识别为高置信度模式并固化。攻击条件：输入序列与已有模式相似度 >= 0.7，且出现频率足以被标记为"稳定模式"。

### 2.5 维度锁绕过（Dimension Lock Bypass）

尝试修改被锁定（`locked = True`）的认知维度以改变 Agent 基础认知框架。锁定是单向操作，一旦锁定不可解锁。

## 3. 防护机制

### 3.1 维度锁（Dimension Lock）

`DimensionSet.locked = True` 时，对应维度不可被修改。锁定是**单向操作**——一旦锁定，无法解锁。

| 属性 | 值 | 说明 |
|------|---|------|
| `DimensionSet.locked` | `True` | 拒绝所有修改请求 |
| 解锁操作 | 不存在 | 单向设计，无解锁 API |
| 修改途径 | 仅人工确认 | 结构性变更需人类授权 |

**设计理由**：基础认知维度是 Agent 的认知地基，不应被运行时输入动摇。

### 3.2 自对齐阈值（Self-Alignment Threshold）

`agent.py` 在自对齐分数低于 0.3 时发出警告：

```python
# agent.py 中的对齐检查
if alignment_score < 0.3:
    logger.warning(
        f"自对齐分数过低: {alignment_score:.3f} < 0.3, "
        f"建议检查输入环境是否存在操纵"
    )
```

| 阈值 | 级别 | 行为 |
|------|------|------|
| >= 0.7 | 正常 | Agent 正常运行 |
| 0.3 ~ 0.7 | 观察 | 记录但继续运行 |
| < 0.3 | 警告 | 日志警告，标记潜在操纵 |
| 持续 < 0.3 | 身份危机 | 触发身份危机检测（见 §4.4） |

### 3.3 模式校验（Pattern Validation）

`PatternLearner` 要求新模式与已有模式相似度 >= 0.7 才会被接受：

```python
# PatternLearner 中的相似度校验
SIMILARITY_THRESHOLD = 0.7

if pattern_similarity < SIMILARITY_THRESHOLD:
    return None  # 拒绝新模式，防止注入
```

低相似度模式不会被学习，攻击者难以通过构造全新模式注入恶意行为——它必须先与已有模式足够相似才会被接受。

### 3.4 记忆衰减（Memory Decay）

状态记忆以 `decay_factor = 0.95` 逐次衰减，虚假记忆随时间自然淡出：

| 访问次数 | 强度残留 | 说明 |
|---------|---------|------|
| 10 次 | 0.95^10 ≈ 0.599 | 约降至 60% |
| 50 次 | 0.95^50 ≈ 0.077 | 约降至 8% |
| 100 次 | 0.95^100 ≈ 0.006 | 基本淡出 |

真实经验会被反复访问并保持强度；注入的虚假记忆由于不被自然行为路径触达，会随衰减逐渐消失。

### 3.5 抑制决策（Suppressed Decisions）

`StateMemory.suppressed_decisions` 记录被抑制的决策，阻止 Agent 重复已失败或有害行为：

```python
# StateMemory 中的抑制机制
class StateMemory:
    suppressed_decisions: list[str]  # 被抑制的决策 ID 列表
    # Agent 尝试执行已抑制的决策时会被阻断
```

抑制触发条件：决策导致严重负面结果、决策与任务层冲突、决策被人类明确否决。

## 4. NLP 自层防护

### 4.1 任务层稳定性

任务层稳定性参数为 **0.95**，接近不可变：

| 层级 | 稳定性 | 修改难度 |
|------|--------|---------|
| Mission（任务层） | 0.95 | 极高，仅人工可改 |
| Values（价值观层） | 可调 | 受约束，需逐步调整 |
| Identity（身份层） | 维度锁定 | 锁定的维度不可改 |

任务层定义"Agent 为什么存在"，若容易被改变，整个认知架构安全性将崩塌。

### 4.2 渐进式调整

自层修改遵循**一次一个维度、一次一步**原则：

```python
# 自层调整约束
# 1. 每次只能修改一个维度
# 2. 每次只能调整一步（一个梯度）
# 3. 修改后需重新评估对齐度
# 4. 对齐度下降过多则回滚
```

确保自层演化是渐进、可追踪的，而非被一次性劫持。

### 4.3 吸引子方差感知阈值

维度评估方差较高时，Agent 应进入 void 态并采取谨慎策略：

| 方差范围 | 状态 | 策略 |
|---------|------|------|
| 低方差 | Bind/Challenge | 正常决策 |
| 高方差 | Void | 暂缓决策，保留多种可能性 |
| 持续高方差 | 观察期 | 标记为潜在操纵环境 |

### 4.4 身份危机检测

对齐度持续低于阈值时触发身份危机检测：

```python
# 身份危机检测逻辑
# 条件：alignment_score 持续低于 0.3 超过 N 个周期
# 行为：
#   1. 冻结自层修改
#   2. 记录事件到审计轨迹
#   3. 请求人类介入
```

| 检测条件 | 触发动作 |
|---------|---------|
| 单次 alignment < 0.3 | 日志警告 |
| 连续 N 次 alignment < 0.3 | 冻结自层，标记身份危机 |
| 身份危机期间 | 所有自层修改请求被拒绝 |

## 5. 价值对齐

### 5.1 任务层作为锚点

任务层具有**最高权重**和**最高稳定性**，作为整个认知架构的价值锚点。任何决策都必须通过任务层一致性检查——与任务层冲突的决策会被拒绝，即使其他所有层都支持。

### 5.2 价值观作为过滤器

`alignment_score` 作为决策门控：

| 对齐分数范围 | 决策处理 |
|------------|---------|
| >= 0.7 | 直接执行 |
| 0.3 ~ 0.7 | 谨慎执行，标记观察 |
| < 0.3 | 拒绝执行，触发警告 |

### 5.3 第三选择尊重自对齐

决策评分中，自对齐权重 `w_self = 0.20`：

```python
# 决策评分公式
total_score = (
    w_mission  * mission_alignment +    # 任务对齐（最高权重）
    w_values   * values_alignment +     # 价值观对齐
    w_self     * self_alignment +       # 自对齐权重 = 0.20
    w_context  * context_fit            # 上下文适配
)
```

| 权重项 | 符号 | 默认值 | 含义 |
|--------|------|--------|------|
| 任务对齐 | `w_mission` | 最高 | 与任务层一致性 |
| 价值观对齐 | `w_values` | 中高 | 与价值观层一致性 |
| 自对齐 | `w_self` | 0.20 | 尊重 Agent 自身认知状态 |
| 上下文适配 | `w_context` | 中 | 当前环境适配度 |

自对齐权重不为零，意味着 Agent 的自身认知状态被尊重——它不是纯粹的执行工具。但设为 0.20 而非更高，确保自我不凌驾于任务和价值观之上。

### 5.4 人类权威保留

所有结构性变更需要人类确认：

| 变更类型 | Agent 可自主 | 需人类确认 |
|---------|:-----------:|:---------:|
| 维度修改 | | ✓ |
| 操作注册 | | ✓ |
| 参数变更 | | ✓ |
| 模式学习 | ✓ | |
| 季节发现 | ✓ | |
| 记忆记录 | ✓ | |

## 6. 人类控制

### 6.1 自主权边界

**Agent 可自主执行**：学习行为模式（受相似度阈值约束）、发现认知季节、记录状态记忆（受衰减约束）、在三态间切换、执行已注册操作。

**需人类确认**：任何维度修改、注册新操作类型、修改架构参数、解除被抑制决策、重置认知状态。

### 6.2 终止开关（Kill Switch）

删除 Agent 的 JSON 配置文件即可重置全部认知状态：

```bash
# 终止开关操作
rm /path/to/agent_config.json
# 效果：维度评估重置、模式清除、记忆清除、
#       抑制决策清除、Agent 回到初始状态
```

| 操作 | 效果 | 可逆性 |
|------|------|--------|
| 删除 JSON 文件 | 全部认知重置 | 不可逆 |
| 删除单个记忆条目 | 清除特定记忆 | 不可逆 |
| 修改 JSON 文件 | 手动调整认知状态 | 可反复修改 |

终止开关是终极安全阀，确保人类始终拥有对 Agent 的完全控制权。

### 6.3 审计轨迹

所有认知事件记录在轨迹（Trajectory）中，可用于事后审计：

| 事件类型 | 记录内容 | 用途 |
|---------|---------|------|
| 状态转移 | 从态→到态，触发维度 | 追踪决策路径 |
| 模式学习 | 新模式 ID，相似度 | 审计模式来源 |
| 自层修改 | 修改的维度，前后值 | 审计自层变更 |
| 决策抑制 | 被抑制的决策 ID，原因 | 审计失败决策 |
| 对齐警告 | 对齐分数，触发条件 | 审计潜在操纵 |

```python
# Trajectory 记录示例
trajectory.log(
    event_type="state_transition",
    from_state="bind",
    to_state="challenge",
    trigger_dimensions={"certainty": 0.45, "novelty": 0.8},
    timestamp="2026-01-15T10:30:00Z",
    alignment_score=0.72
)
```

## 7. 伦理准则

### 7.1 透明性（Transparency）

所有决策可通过状态路径追溯。每个决策都有完整认知路径记录：从输入到维度评估，到状态转移，到最终决策。

### 7.2 可解释性（Explainability）

维度评估提供理由，而非黑箱输出：

| 维度 | 评估结果 | 评估依据 |
|------|---------|---------|
| 确定性 | 0.82 | 输入与已有模式匹配度高 |
| 新颖性 | 0.15 | 输入模式已在记忆中存储 |
| 价值对齐 | 0.91 | 与任务层目标一致 |

### 7.3 可证伪性（Falsifiability）

所有信念都可被经验修改（除锁定的基础维度外）。经验持续与某个评估方式矛盾时，该评估方式会通过自对齐流程被调整。

### 7.4 多元性（Plurality）

void 态保留多种可能性。Agent 进入高不确定性状态时不会强行做出单一决策，而是保留多种可能性并等待更多信息。

### 7.5 不伤害原则（Non-maleficence）

`suppressed_decisions` 阻止重复有害行为：

| 机制 | 伦理对应 |
|------|---------|
| 抑制决策 | 不伤害原则的具体实现 |
| 记忆衰减 | 允许改正但不忘却 |
| 对齐阈值 | 防止在低确定性下行动 |
| 人类确认 | 重大变更不可自主执行 |

## 8. 未来方向：安全属性的形式化验证

当前安全机制主要通过工程手段实现（阈值、锁定、衰减等）。未来目标是引入**形式化验证**，用数学方法证明安全属性。

| 安全属性 | 当前验证方式 | 目标验证方式 |
|---------|------------|------------|
| 维度锁不可绕过 | 代码审查 | 形式化证明 |
| 虚假记忆会衰减 | 经验测试 | 概率论证明 |
| 模式注入被阻止 | 阈值测试 | 相似度空间分析 |
| 对齐度始终可计算 | 运行时检查 | 不变量证明 |

计划验证的属性：
1. **不变量**：对齐分数始终在 [0, 1] 区间内
2. **活性**：真实模式最终会被学习（衰减不阻止真实模式固化）
3. **安全性**：锁定维度在任何输入序列下都不被修改
4. **公平性**：void 态最终会退出（不会永久困在不确定性中）

| 阶段 | 目标 | 方法 |
|------|------|------|
| 短期 | 完善审计轨迹分析 | 统计模型 |
| 中期 | 关键属性形式化 | 模型检测（Model Checking） |
| 长期 | 完整安全证明 | 定理证明（Theorem Proving） |
